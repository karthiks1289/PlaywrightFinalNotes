Important TypeScript methods · One-line usage · Return types

A practical reference for popup capture, tabs/pages, navigation, assertions and cleanup. Use the return type to understand what each method gives back.

2. Popup and new-page capturing Core interview APIs

MethodOne-line usageReturn type
page.waitForEvent("popup")Wait for a popup opened by the current page.Promise<Page>
context.waitForEvent("page")Wait for a new page opened anywhere in this context.Promise<Page>
page.on("popup", handler)Listen continuously for popups opened by this page.void
context.on("page", handler)Listen continuously for new pages in this context.void
page.once("popup", handler)Listen for only the next popup event.void
popup.opener()Get the page that opened this popup, if available.Promise<Page | null>
Choose the right API:
page.waitForEvent("popup") = popup from the current page.
context.waitForEvent("page") = a new page anywhere in the context.
context.on("page") = continuously monitor new pages.

3. Capture popup and click together

MethodOne-line usageReturn type
Promise.all()Wait for the popup event and perform the click together.Promise<Array / tuple>
const [popup] = await Promise.all([
  page.waitForEvent("popup"),
  page.getByRole("button", { name: "Open Window" }).click()
]);

The first promise registers the popup wait before the click starts. The captured popup is a Page object.

5. Find and identify pages

MethodOne-line usageReturn type
context.pages()Get an array of currently open pages.Page[]
pages.find()Find the first page matching a synchronous condition, such as URL.Page | undefined
page.url()Read the current page URL.string
page.title()Read the current page title asynchronously.Promise<string>
// Find by URL
const invoicePage = context.pages().find(
  p => p.url().includes("/invoices")
);

// Find by title: title() is asynchronous, so use for...of
let pageWithInvoiceTitle;
for (const p of context.pages()) {
  if ((await p.title()).includes("Invoice")) {
    pageWithInvoiceTitle = p;
    break;
  }
}

Important: find() does not wait for async callbacks. Use for...of when checking an async method such as page.title().

7. Waits and assertions inside popups

MethodOne-line usageReturn type
locator.waitFor()Wait for locator state: attached, detached, visible or hidden.Promise<void>
expect(locator).toBeVisible()Retry until the element is visible.Promise<void>
expect(locator).toBeHidden()Retry until the element is hidden or detached.Promise<void>
expect(locator).toHaveText()Retry until the element has the expected text.Promise<void>
expect(locator).toHaveValue()Retry until an input has the expected value.Promise<void>
expect(locator).toBeEnabled()Retry until the element is enabled.Promise<void>
expect(popup).toHaveTitle()Retry until the page title matches.Promise<void>
expect(popup).toHaveURL()Retry until the page URL matches.Promise<void>
Remember: Actions such as locator.click() have built-in actionability auto-waiting. Use web-first assertions when you need to verify that a UI state eventually becomes true.

9. Important interview distinctions

  • New tab/new window vs new context: A popup opened through normal browser popup behavior is generally a new Page in the same context. A separate browser process/context is a different case.
  • page.waitForEvent("popup") vs context.waitForEvent("page"): Popup from the current page vs a new page anywhere in the context.
  • page.url() vs page.title(): URL is synchronous; title is asynchronous.
  • context.pages() vs browser.contexts(): Pages in one context vs contexts in one browser.
  • page.close() vs context.close(): Close one page vs close all pages in one context.
  • context.close() vs browser.close(): Close one session vs close the browser.
  • page.isClosed() vs page.on("close"): Check current state vs listen for a close event.
  • waitForURL() vs expect(page).toHaveURL(): Wait for a URL condition vs make a retrying URL assertion.
