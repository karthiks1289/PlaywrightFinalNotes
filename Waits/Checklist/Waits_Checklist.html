Playwright Waits API Checklist

A method-by-method revision sheet: where the API belongs, its arguments, return type, practical syntax, and the mistake to avoid. Check items as you learn them. This file works offline.

1. Core locator waiting and action auto-waiting

locator.waitFor(options?)
Owner: Locator · Returns: Promise<void>

Wait until the locator reaches a DOM/visibility state.

Arguments
state?: 'attached' | 'detached' | 'visible' | 'hidden' (default: 'visible'); timeout?: number; signal?: AbortSignal (newer versions).
Example
await page.getByText('Saved').waitFor({ state: 'visible', timeout: 8000 });
Remember
Use when you need an explicit locator-state wait. Prefer a web-first assertion when the goal is to verify expected UI.
locator.click(options?)
Owner: Locator · Returns: Promise<void>

Clicks after Playwright's actionability checks pass.

Arguments
timeout?: number; force?: boolean; noWaitAfter?: boolean (deprecated/no effect); position?: { x, y }; modifiers?: Array<'Alt'|'Control'|'Meta'|'Shift'>; button?: 'left'|'right'|'middle'; clickCount?: number; delay?: number; trial?: boolean; signal?: AbortSignal; scroll?: 'auto'|'none' (version-dependent).
Example
await page.getByRole('button', { name: 'Save' }).click({ timeout: 10000 });
Remember
Usually no separate wait is needed before click. Do not use force to hide a real user-facing problem.
locator.dblclick(options?)
Owner: Locator · Returns: Promise<void>

Double-clicks after actionability checks.

Arguments
Shares click-style options such as timeout, force, position, button, modifiers, delay, trial and signal.
Example
await page.getByText('Record').dblclick({ timeout: 8000 });
Remember
Use only when the application requires a double-click.
locator.fill(value, options?)
Owner: Locator · Returns: Promise<void>

Fills an input after waiting for it to be ready.

Arguments
value: string; options: timeout?: number; force?: boolean; noWaitAfter?: boolean (deprecated/no effect); signal?: AbortSignal.
Example
await page.getByLabel('Email').fill('qa@example.com', { timeout: 5000 });
Remember
Preferred for normal text entry; does not type each key individually.
locator.press(key, options?)
Owner: Locator · Returns: Promise<void>

Focuses the element and presses a key or key combination.

Arguments
key: string (examples: 'Enter', 'Tab', 'Control+A'); options: timeout?: number; noWaitAfter?: boolean (deprecated/no effect); signal?: AbortSignal.
Example
await page.getByLabel('Search').press('Enter');
Remember
For a sequence of characters use fill() in most cases.
locator.pressSequentially(text, options?)
Owner: Locator · Returns: Promise<void>

Types text character by character for apps with special keyboard handling.

Arguments
text: string; options: delay?: number (ms between key presses); timeout?: number; signal?: AbortSignal.
Example
await page.getByLabel('OTP').pressSequentially('123456', { delay: 100 });
Remember
Use only when individual key events matter; fill() is normally better.
locator.check(options?) / uncheck(options?)
Owner: Locator · Returns: Promise<void>

Checks or unchecks a checkbox/radio after actionability checks.

Arguments
timeout?: number; force?: boolean; trial?: boolean; position?: { x, y }; noWaitAfter?: boolean (deprecated/no effect); signal?: AbortSignal.
Example
await page.getByRole('checkbox', { name: 'Terms' }).check();
Remember
These actions verify the resulting checked state; use expect(...).toBeChecked() when asserting later.
locator.setChecked(checked, options?)
Owner: Locator · Returns: Promise<void>

Sets checkbox/radio state to true or false.

Arguments
checked: boolean; options include timeout?: number; force?: boolean; trial?: boolean; signal?: AbortSignal.
Example
await page.getByRole('checkbox').setChecked(true);
Remember
Useful when the desired state is known; avoids separate check/uncheck branching.
locator.selectOption(values, options?)
Owner: Locator · Returns: Promise<Array<string>>

Waits for matching options to exist and selects them in a native select.

Arguments
values: string | { label?: string; value?: string; index?: number } | Array of these; options: timeout?: number; force?: boolean; signal?: AbortSignal.
Example
await page.getByLabel('Country').selectOption({ label: 'India' });
Remember
Return value is the selected option value(s). This is for HTML select elements, not custom dropdowns.
locator.setInputFiles(files, options?)
Owner: Locator · Returns: Promise<void>

Sets files on an input[type=file].

Arguments
files: string | Array<string> | { name: string; mimeType: string; buffer: Buffer } | Array of file payloads; options: timeout?: number; noWaitAfter?: boolean (deprecated/no effect); signal?: AbortSignal.
Example
await page.getByLabel('Upload').setInputFiles('tests/data/report.pdf');
Remember
Waits for the file input to be actionable; use file chooser event for UI that opens a chooser without a known input.
locator.hover(options?) / focus(options?) / scrollIntoViewIfNeeded(options?)
Owner: Locator · Returns: Promise<void>

These actions wait for the relevant actionability/scroll conditions before acting.

Arguments
Common option: timeout?: number; hover also supports force, position, modifiers, trial and signal; focus supports timeout/signal; scrollIntoViewIfNeeded supports timeout/signal.
Example
await menu.hover({ timeout: 5000 });
Remember
Do not confuse scrolling into view with waiting for an application data load.

2. Web-first assertions that automatically retry

expect(locator).toBeVisible(options?)
Owner: expect + Locator · Returns: Promise<void>

Retries until the locator is visible or the assertion timeout expires.

Arguments
options?: { timeout?: number }.
Example
await expect(page.getByText('Order submitted')).toBeVisible({ timeout: 10000 });
Remember
Best default for checking that UI appears. Default assertion timeout is 5 seconds.
expect(locator).toBeHidden(options?) / toBeAttached(options?)
Owner: expect + Locator · Returns: Promise<void>

Retries until hidden or attached state is true.

Arguments
options?: { timeout?: number }.
Example
await expect(page.locator('.spinner')).toBeHidden();
Remember
Hidden can mean not visible or detached; attached means present in DOM.
expect(locator).toHaveText(expected, options?) / toContainText(expected, options?)
Owner: expect + Locator · Returns: Promise<void>

Retries until text matches or contains the expected value.

Arguments
expected: string | RegExp | Array<string | RegExp>; options: timeout?: number; useInnerText?: boolean; ignoreCase?: boolean (where supported).
Example
await expect(status).toHaveText('Completed', { timeout: 12000 });
Remember
Use for asynchronously rendered text rather than reading text once and asserting immediately.
expect(locator).toHaveCount(count, options?)
Owner: expect + Locator · Returns: Promise<void>

Retries until the locator matches the expected number of elements.

Arguments
count: number; options?: { timeout?: number }.
Example
await expect(page.getByRole('row')).toHaveCount(6);
Remember
Prefer this over locator.count() for a changing UI.
expect(locator).toHaveAttribute(name, value?, options?) / toHaveClass(value, options?)
Owner: expect + Locator · Returns: Promise<void>

Retries until an attribute or CSS class condition matches.

Arguments
attribute name: string; expected value: string | RegExp (optional for attribute presence); class: string | RegExp | Array; options include timeout?: number.
Example
await expect(saveButton).toHaveAttribute('aria-disabled', 'false');
Remember
Useful for checking state attributes, but prefer role-based user-visible checks where possible.
expect(locator).toBeEnabled(options?) / toBeDisabled(options?) / toBeEditable(options?)
Owner: expect + Locator · Returns: Promise<void>

Retries until the control reaches the requested interaction state.

Arguments
options?: { timeout?: number }.
Example
await expect(submitButton).toBeEnabled();
Remember
An enabled assertion is not a replacement for click() auto-waiting; use it when enabled state is itself a requirement.
expect(locator).toBeChecked(options?) / toBeFocused(options?) / toBeInViewport(options?)
Owner: expect + Locator · Returns: Promise<void>

Retries until checked, focused or intersecting viewport condition is met.

Arguments
options?: { timeout?: number }; toBeInViewport also accepts ratio?: number (0 to 1).
Example
await expect(termsCheckbox).toBeChecked();
Remember
Useful for UI state verification.
expect(page).toHaveURL(url, options?) / toHaveTitle(title, options?)
Owner: expect + Page · Returns: Promise<void>

Retries until page URL or title matches.

Arguments
expected: string | RegExp; options include timeout?: number; URL assertion supports ignoreCase?: boolean in current API.
Example
await expect(page).toHaveURL(/\/dashboard$/);
Remember
Prefer this assertion when verifying final URL/title. Use page.waitForURL when synchronizing a navigation before another step.
expect(response).toBeOK(options?)
Owner: expect + APIResponse/Response · Returns: Promise<void>

Retries? This is an assertion on a response object already received; it does not wait for a response event.

Arguments
options?: { timeout?: number } for supported assertion API.
Example
expect(response.ok()).toBeTruthy(); // Or use supported response assertion APIs for your version.
Remember
Do not mistake response assertions for a network wait. First capture/wait for the response.

3. Page navigation and document lifecycle waits

page.goto(url, options?)
Owner: Page · Returns: Promise<Response | null>

Navigates to URL and waits for the chosen navigation lifecycle state.

Arguments
url: string; options: timeout?: number; waitUntil?: 'load' | 'domcontentloaded' | 'networkidle' | 'commit'; referer?: string.
Example
await page.goto('/orders', { waitUntil: 'domcontentloaded', timeout: 30000 });
Remember
waitUntil defaults to load. networkidle is discouraged for tests; assert the business UI state instead.
page.waitForURL(url, options?)
Owner: Page · Returns: Promise<void>

Waits for the main frame to navigate to a matching URL.

Arguments
url: string glob | RegExp | URLPattern | (url: URL) => boolean; options: waitUntil?: 'load'|'domcontentloaded'|'networkidle'|'commit'; timeout?: number.
Example
const nav = page.waitForURL('**/confirmation'); await submit.click(); await nav;
Remember
Set up the wait before the action that triggers navigation to avoid missing a fast navigation.
page.waitForLoadState(state?, options?)
Owner: Page · Returns: Promise<void>

Waits for the current document's lifecycle state.

Arguments
state?: 'load' | 'domcontentloaded' | 'networkidle' (default load); options: timeout?: number; signal?: AbortSignal.
Example
await page.waitForLoadState('domcontentloaded');
Remember
Navigation must already have been committed. Often unnecessary. networkidle is discouraged for test readiness.
page.waitForNavigation(options?)
Owner: Page · Returns: Promise<Response | null>

Legacy navigation wait; resolves when navigation occurs.

Arguments
options: url?: string | RegExp | predicate; waitUntil?: 'load'|'domcontentloaded'|'networkidle'|'commit'; timeout?: number.
Example
Prefer page.waitForURL() for modern URL synchronization.
Remember
Deprecated/discouraged due to race conditions and ambiguity with modern navigation. Do not use in new tests.

4. Events: popup, new tab, download, file chooser, dialog

page.waitForEvent(event, optionsOrPredicate?)
Owner: Page · Returns: Promise<EventPayload>

Waits for a page event and returns its event payload.

Arguments
event: string (e.g. 'popup', 'download', 'filechooser', 'dialog'); options/predicate: predicate?: (event) => boolean | Promise<boolean>; timeout?: number.
Example
const popupPromise = page.waitForEvent('popup'); await page.getByRole('link', { name: 'Open' }).click(); const popup = await popupPromise;
Remember
Create the promise before clicking. For a popup created by this page, page.waitForEvent('popup') is appropriate.
context.waitForEvent('page', optionsOrPredicate?)
Owner: BrowserContext · Returns: Promise<Page>

Waits for any new page/tab created anywhere in that browser context.

Arguments
event: 'page'; options: predicate?: (page) => boolean | Promise<boolean>; timeout?: number.
Example
const pagePromise = context.waitForEvent('page'); await trigger.click(); const newPage = await pagePromise;
Remember
Use when you need to catch a new page at context level, including pages not directly opened by the current page.
page.waitForEvent('download')
Owner: Page · Returns: Promise<Download>

Waits for a download triggered by the page.

Arguments
Optional predicate can inspect suggestedFilename(); timeout?: number.
Example
const downloadPromise = page.waitForEvent('download'); await downloadButton.click(); const download = await downloadPromise;
Remember
Then inspect download.suggestedFilename() or await download.saveAs(path).
page.waitForEvent('filechooser')
Owner: Page · Returns: Promise<FileChooser>

Waits for the file chooser event.

Arguments
Optional predicate?: (fileChooser) => boolean; timeout?: number.
Example
const chooserPromise = page.waitForEvent('filechooser'); await uploadButton.click(); const chooser = await chooserPromise; await chooser.setFiles('file.pdf');
Remember
Register the wait before clicking the upload control.
page.waitForEvent('dialog')
Owner: Page · Returns: Promise<Dialog>

Waits for JavaScript alert/confirm/prompt dialog event.

Arguments
Optional predicate?: (dialog) => boolean; timeout?: number.
Example
const dialogPromise = page.waitForEvent('dialog'); await deleteButton.click(); const dialog = await dialogPromise; await dialog.accept();
Remember
If a dialog listener is added, it must handle/accept/dismiss it or the page can remain blocked.

5. Network synchronization

page.waitForRequest(urlOrPredicate, options?)
Owner: Page · Returns: Promise<Request>

Waits for a matching outgoing network request.

Arguments
urlOrPredicate: string | RegExp | (request: Request) => boolean | Promise<boolean>; options: timeout?: number (default 30 seconds).
Example
const reqPromise = page.waitForRequest(req => req.url().includes('/api/orders') && req.method() === 'POST'); await save.click(); const req = await reqPromise;
Remember
It confirms the request was sent, not that the server successfully processed it.
page.waitForResponse(urlOrPredicate, options?)
Owner: Page · Returns: Promise<Response>

Waits for a matching network response.

Arguments
urlOrPredicate: string | RegExp | (response: Response) => boolean | Promise<boolean>; options: timeout?: number (default 30 seconds).
Example
const resPromise = page.waitForResponse(res => res.url().includes('/api/orders') && res.status() === 201); await save.click(); const res = await resPromise;
Remember
Usually the best network signal for a user action that triggers an API call. Also assert UI outcome.
request/response predicate methods
Owner: Request / Response · Returns: boolean or values

Build precise matching logic for the wait predicate.

Arguments
Request: url(), method(), resourceType(), postData(); Response: url(), status(), ok(), request(), headers().
Example
res => res.url().includes('/api') && res.status() === 200
Remember
Avoid matching only a generic URL if several requests use the same endpoint.

6. Custom condition and polling waits

page.waitForFunction(pageFunction, arg?, options?)
Owner: Page · Returns: Promise<JSHandle>

Repeatedly evaluates a function in the browser until it returns a truthy value.

Arguments
pageFunction: function | string; arg?: serializable argument; options: polling?: number | 'raf'; timeout?: number; signal?: AbortSignal.
Example
await page.waitForFunction(() => document.querySelectorAll('.result-row').length === 10, null, { polling: 250, timeout: 10000 });
Remember
Advanced tool. Prefer locator assertions when the condition is about visible UI. Returns a JSHandle for the truthy result.
expect.poll(callback, options?)
Owner: expect · Returns: Promise<void> after matcher

Repeatedly calls a callback and retries the attached assertion.

Arguments
callback: () => value | Promise<value>; options: message?: string; timeout?: number (default 5 seconds); intervals?: number[].
Example
await expect.poll(async () => (await page.request.get('/api/health')).status(), { timeout: 15000, intervals: [500, 1000, 2000] }).toBe(200);
Remember
Best for polling API/backend state or values not represented by one locator.
expect(callback).toPass(options?)
Owner: expect · Returns: Promise<void>

Retries a block of assertions until the whole block passes.

Arguments
callback: () => void | Promise<void>; options: timeout?: number; intervals?: number[]. Defaults for intervals are [100, 250, 500, 1000]; default timeout is 0.
Example
await expect(async () => { await expect(status).toHaveText('Ready'); await expect(count).toHaveText('5'); }).toPass({ timeout: 10000 });
Remember
Use carefully: retries the entire callback, so avoid repeating non-idempotent actions such as placing an order.

7. Timeout controls and defaults

testConfig.timeout
Owner: playwright.config.ts · Returns: number (ms)

Maximum duration for an individual test.

Arguments
Top-level timeout: number; default 30,000 ms.
Example
export default defineConfig({ timeout: 45_000 });
Remember
Includes test function, test-scoped fixture setup and beforeEach. Separate timeout accounting applies to teardown/afterEach.
testConfig.expect.timeout
Owner: playwright.config.ts · Returns: number (ms)

Default timeout for auto-retrying assertions.

Arguments
expect: { timeout: number }; default 5,000 ms.
Example
expect: { timeout: 8000 }
Remember
Separate from test timeout.
testOptions.actionTimeout
Owner: playwright.config.ts use · Returns: number (ms)

Default timeout for actions such as click/fill.

Arguments
use: { actionTimeout: number }; default 0 (no limit).
Example
use: { actionTimeout: 10000 }
Remember
Can be overridden per action with { timeout: ... }.
testOptions.navigationTimeout
Owner: playwright.config.ts use · Returns: number (ms)

Default timeout for navigation actions.

Arguments
use: { navigationTimeout: number }; default 0 (no limit).
Example
use: { navigationTimeout: 30000 }
Remember
Can be overridden per navigation operation.
testConfig.globalTimeout
Owner: playwright.config.ts · Returns: number (ms)

Maximum duration for the complete test run.

Arguments
globalTimeout: number; default 0 (disabled).
Example
globalTimeout: 3_600_000
Remember
Not the timeout for each individual test.
test.setTimeout(timeout) / test.slow()
Owner: Test runner · Returns: void

Changes the timeout for a test; slow() triples the default test timeout.

Arguments
setTimeout(timeout: number); slow() has no argument.
Example
test.setTimeout(90000);
Remember
Use for a genuinely slow test, not to mask synchronization bugs.
testInfo.setTimeout(timeout)
Owner: TestInfo · Returns: void

Changes timeout for the current test/hook context.

Arguments
timeout: number (ms).
Example
testInfo.setTimeout(testInfo.timeout + 30000);
Remember
Useful in hooks when the required timeout depends on current test timeout.
page.setDefaultTimeout(timeout) / context.setDefaultTimeout(timeout)
Owner: Page / BrowserContext · Returns: void

Sets default timeout for supported operations in that page/context.

Arguments
timeout: number (ms).
Example
page.setDefaultTimeout(10000);
Remember
Affects many operations that accept timeout; config-level actionTimeout is often clearer in Test projects.
page.setDefaultNavigationTimeout(timeout) / context.setDefaultNavigationTimeout(timeout)
Owner: Page / BrowserContext · Returns: void

Sets default timeout for navigation operations.

Arguments
timeout: number (ms).
Example
page.setDefaultNavigationTimeout(30000);
Remember
Navigation-specific default takes precedence over general default timeout for navigation.
fixture option timeout / webServer.timeout
Owner: playwright.config.ts · Returns: number (ms)

Gives a fixture its own setup budget or controls how long Playwright waits for a web server to start.

Arguments
Fixture: { timeout: number }; webServer: { timeout: number }; webServer default 60,000 ms.
Example
webServer: { command: 'npm run start', url: 'http://127.0.0.1:3000', timeout: 120000 }
Remember
Do not confuse application navigation timeout with local server startup timeout.

8. Checks that are often mistaken for waits

locator.isVisible() / isHidden() / isEnabled() / isChecked()
Owner: Locator · Returns: Promise<boolean>

Returns the current state immediately; these do not retry until the state changes.

Arguments
No timeout option for these state checks.
Example
const visibleNow = await banner.isVisible();
Remember
Use expect(locator).toBeVisible() when you need retry behavior.
locator.count()
Owner: Locator · Returns: Promise<number>

Returns the current number of matching elements; does not wait for a desired count.

Arguments
No timeout option.
Example
const rowsNow = await page.getByRole('row').count();
Remember
Use expect(locator).toHaveCount(expected) for an asynchronously changing count.
locator.all() / allTextContents() / allInnerTexts()
Owner: Locator · Returns: Promise<Locator[]> / Promise<string[]>

Reads the current matching list; does not wait for the full list to finish loading.

Arguments
No wait timeout parameter.
Example
await expect(rows).toHaveCount(5); const allRows = await rows.all();
Remember
Wait for a stable expected state first, then read the collection.
page.waitForTimeout(milliseconds)
Owner: Page · Returns: Promise<void>

Fixed sleep. Waits only for elapsed time, not for an application condition.

Arguments
milliseconds: number.
Example
await page.waitForTimeout(1000);
Remember
Discouraged for production tests; use only for debugging.

9. One-page timeout configuration example

Use this as a reference shape, then choose values that match your application's real behavior. These are example values, not universal recommendations.

import { defineConfig } from '@playwright/test';

export default defineConfig({
  timeout: 30_000,              // one test
  expect: { timeout: 5_000 },  // retrying assertions
  globalTimeout: 3_600_000,    // entire test run

  use: {
    actionTimeout: 10_000,      // click/fill etc.
    navigationTimeout: 30_000,  // navigation operations
  },

  webServer: {
    command: 'npm run start',
    url: 'http://127.0.0.1:3000',
    timeout: 120_000,           // wait for local server startup
    reuseExistingServer: !process.env.CI,
  },
});
Remember the clocks: test = timeout · assertion = expect.timeout · action = actionTimeout · navigation = navigationTimeout · suite = globalTimeout · server startup = webServer.timeout.

10. High-value rules to memorise

  • Start event, request, response, popup and download waits before the action that triggers them.
  • Prefer expect(locator).toBeVisible() over locator.isVisible() when the UI may appear later.
  • Prefer expect(locator).toHaveCount() over locator.count() when the list loads asynchronously.
  • Prefer page.waitForURL() over deprecated page.waitForNavigation().
  • Do not use networkidle as a general “application is ready” signal; assert the user-visible business condition.
  • A timeout is a maximum allowed wait, not a command to pause for that full duration.
  • Increasing timeouts does not fix bad locators, overlays, missing data, or incorrect synchronization.
  • force: true bypasses actionability checks; use it only when bypassing normal user-like checks is intentional.
